# Granular transport and contact

The bed uses paired transfers on eight links per cell. Cardinal weights are 2/3 and diagonal weights are 1/6: the resulting nine-point stencil has the same second-order diffusion scale as the former cardinal stencil, with isotropic fourth-order truncation error in the linear regime. Repose thresholds use the actual link length, including the diagonal sqrt(2) factor. This reduces grid-aligned flow bias; it is not a fully rotation-invariant granular continuum model.

All eight outgoing amounts share one available-height limiter. Integration gathers the opposite link from each valid neighbor, including at edges and corners. Never clamp the integrated height to hide a conservation failure. Particle launch reserves must subtract the sum of all eight transfers, and launch direction and bed velocity must include diagonal displacement.

Pointer motion is resampled by travelled bed distance rather than raw event count. The queue retains real DOM timestamps on the resulting short segments, so geometry follows the same path distance regardless of pointer reporting rate while velocity still reflects how quickly that path was travelled. Several distance-bounded segments can be consumed in one fixed simulation step, preventing fast gestures from lagging behind the visible pointer or losing old movement under a capped event queue.

Multiple pointer IDs are tracked independently. Each substep accepts a bounded batch of simultaneous contact segments and rasterizes them into one compact per-cell contact field before granular transport. Transport therefore sees combined mouse, pen, or multi-finger contact without running a separate full sand solve per pointer. Overlapping contacts select the strongest local pressure/motion response while preserving the broadest disturbed shell.

Pointer position by itself is observational only. The input queue emits tool contact only after a held pointer has actually moved. Hovering, moving the cursor without pressing, or holding a stationary press therefore cannot displace the bed; this is enforced before the GPU contact field is built rather than relying on a visual-state convention.

The finger remains a swept capsule over the existing heightfield transport, not a separate rigid-body or granular solver. Contact has a target surface based on the configured penetration depth. Forced evacuation is deliberately finite-rate instead of moving the full overlap through one grid edge in a single substep: normal transport handles part of the displacement and the remaining contact correction removes 32–46% of the overlap per step depending on gesture speed. Because neighboring swept segments overlap spatially, the tool still clears its path while avoiding the one-cell mass pileups that produced needle-like leading ridges. Highly supercritical slopes receive a conservative avalanche-rate boost, and a narrow disturbed shell around an active tool temporarily lowers yield resistance so the front bank spreads into a compact bow wave rather than isolated grid spikes. No height blur or post-simulation clamp is used; all smoothing is mass-conserving transport.

Loose grains collide against the same two triangles used by the surface mesh. Contact height and normal come from four neighboring heights, not a nearest-cell staircase. Restitution acts only on incoming normal velocity; Coulomb-style tangential friction dissipates energy. Launching is now tied to conserved transport/activity and bed momentum. Each inactive grain still scans a unique bed cell on the existing bounded schedule, but its launch probability is derived from the ejectable transported mass and local agitation rather than a fixed random chance. Launch direction inherits the bed/transport direction, launch speed inherits local bed momentum, gravity is unchanged, and landed grain mass returns through the fixed-point exchange buffer. This remains a heightfield/ballistic hybrid, not particle-particle contact dynamics or an MPM solver.

The flux buffer costs 8 MiB at 512 squared (4 MiB more than cardinal-only transport). Dispatch count, state buffers, render workload, and fixed-step budget are unchanged. Neighbor work remains eight links per cell; the contact additions are bounded arithmetic inside the same passes. Hardware tests check correctness, not a universal frame-time guarantee.

GPU regressions cover diagonal spread, symmetric diagonal neighbors, edge/corner conservation, bed floor bounds, signed-slope impacts, impact energy loss, redeposition, persistent grooves, gesture-speed momentum/ejection differences, and offscreen rendering. Browser visual review remains manual.
